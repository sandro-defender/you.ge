## 1. Issues fixed

Each fix was first reproduced (failing unit test or HTTP check), then fixed,
then re-verified on the dev server **and** on the built Worker (`vite
preview`).

### Security and authorization

1. **A suspended admin kept a working session.** `PATCH
   /api/admin/users/:id` (the admin UI's endpoint since PR #7) set
   `banned` but kept the sessions. better-auth's admin middleware checks only
   that a session exists, not `banned`, so the suspended admin could call
   `POST /api/auth/admin/unban-user` on themselves (**reproduced: HTTP
   200**). Suspension now deletes the target's sessions, like better-auth's
   own `banUser` (now 401).
2. **Admins could suspend their own account** (reproduced: 200, then locked
   out). Now 400, matching better-auth's `YOU_CANNOT_BAN_YOURSELF`.
3. **Comma roles broke both last-admin guards.** `admin-guards.ts` and the
   `databaseHooks.user.update.before` hook compared `role === "admin"`:
   - a sole `admin,member` admin could demote themselves through either
     path, locking everyone out (reproduced: 200 on both);
   - better-auth `set-role ["admin","member"]` on the only admin was wrongly
     refused (reproduced: 400).

   Both paths now share `canChangeAdminState` / `countOtherActiveAdmins`
   (`hasRole`-based; banned admins do not count as a fallback).
4. **The public `/api/public/home` leaked member-only case-study fields**
   (`challenge`, `solution`, `caseStudy`) to anonymous visitors (reproduced
   with fixture text). They are now stripped by `toPublicTeaser`; the
   member-gated detail API still serves them.
5. **SPA links from public pages skipped the Worker gate.** A signed-out
   visitor clicking "View selected work" got the library shell with "Signed
   in as member." and an API error. Links into gated routes (homepage CTAs
   and cards, nav, "Go to projects") now use `reloadDocument`, so the
   Worker answers 302/403 (verified in router-core: `reloadDocument` →
   `documentNavigation`).

### Broken routes and runtime

6. **Project detail page unreachable.** `projects.$owner.$name.tsx` was
   nested under `projects.tsx`, which renders no `<Outlet />`, so
   `/projects/:owner/:name` showed the library (reproduced in SSR). It is now
   renamed to `projects_.$owner.$name.tsx` (non-nested); the route tree is
   regenerated by the plugin.
7. **The service worker reloaded pages on its own.** `install` called
   `skipWaiting()` and ClientRuntime reloaded on every `controllerchange`:
   - first-time visitors were reloaded once the first worker claimed the page;
   - every deploy reloaded open tabs without consent (unsaved admin edits
     lost).

   Updates now wait for "Reload now", and reloads happen only when an
   existing controller is replaced. Only `ok` navigations are cached;
   `VERSION` is bumped to v3 to purge caches that may hold error pages.
8. **Login raced the Google redirect.** `navigate()` ran after
   `signIn.social`, although better-auth's redirect plugin had already set
   `window.location.href`. The call is removed.
9. **Unread counts were capped at the page size** (8 unread were reported as
   1/6/8 for `limit=1/6/50`). `notificationFeed` now counts with an
   index-backed `COUNT(*)`; the nav fetches `limit=1`.
10. **Fractional `?limit=2.5` caused a 500** (`SQLITE_MISMATCH`, verified
    against local D1). The value is now truncated.
11. **Gated-page loaders made a wasted RPC.** On client navigation,
    `getServerSession()` always returns `null` via `/_serverFn/*`
    (**verified over HTTP with a valid member cookie**), yet each navigation
    or hover-preload cost a Worker request. `loadSessionForRender()` skips
    it in the browser. Copy no longer claims an identity it cannot know, and
    the admin layout keeps its SSR session (`staleTime: Infinity`).

### UI, accessibility and loading states

12. **Homepage widgets showed skeletons forever** on error or empty data.
    They now show a loading state, data, or a clear message.
13. **Projects page:**
    - an empty library no longer says "No projects match those filters";
    - the result count is a `role="status"` live region;
    - Refresh keeps an accessible name while busy.
14. **Spinner-only buttons had no accessible name** while busy (admin
    overview, users, repos, Save). They now carry visually hidden text.
15. **Toasts are announced reliably.** Persistent, visually hidden
    `status`/`alert` regions are used, because a live region inserted
    together with its text is not reliably announced.
16. **Nav:**
    - `hasRole` for the Admin link (an `admin,member` admin lost it);
    - a valid `role="status"` spinner;
    - Escape closes the mobile menu and returns focus;
    - polling skips hidden tabs (README quota warning).
17. **Other markup fixes:**
    - error page: `<main id="content">` (skip-link target) and a labelled
      `<section>`;
    - project tags: `role="list"`;
    - admin repos: `aria-current` on the selected repo, and labelled
      sections instead of unlabelled nested `<aside>`s;
    - users page: unique list keys, and comma roles shown as-is;
    - detail page: no skeleton under an error;
    - login: an `<h1>` in the signed-in state.
18. **Canonical tag on every page.** The root declared
    `canonical → https://you.ge/` on `/login`, the 404 page and gated pages,
    against HANDOVER R7. Now only `/` declares it.
19. **ClientRuntime hydration mismatch.** It read `navigator.onLine` during
    the first render, which mismatched SSR when offline.

## 4. Known issues left as they are (out of scope or need an owner decision)

- **Shared admin notifications.** Notifications for the `admin` audience
  have one `read_at`, so one admin marking them read clears them for all
  admins. Fixing this needs a schema change.
- **Duplicate session requests.** Nav and the homepage each call
  `/api/auth/get-session` (2 requests per page view); de-duplicating needs
  a shared session store.
- **Overview reads every session row.** `/api/admin/overview` reads all
  `session` rows (fine for a handful of users).
- **Uninformative device labels.** "Recent access" shows
  `userAgent.split(" ")[0]`, which is almost always `Mozilla/5.0`.
- **Stuck sync rows.** A Worker killed mid-sync leaves a `running` row; it
  is treated as stale after 15 min, but it stays in the history.
- **Ambiguous label.** The "Visible" stat on `/projects` counts the whole
  visible library, not the filtered result (the count line shows that).
- **Possible dependency upgrade.** See `npm audit` above.
